# Non-Functional Requirements (NFR) — Unit 1: Core Domain & DB Schema

This document defines the quality attributes, security baselines, concurrency rules, and resiliency requirements for Unit 1.

---

## 1. Quality Attributes & Performance Targets

### 1.1 Performance & Latency
- **NFR-PERF-01**: Primary Key lookups by `ApplicationId` (Guid) must complete in $< 10$ms (p95).
- **NFR-PERF-02**: Filtered pagination queries on `AgentApplications` (by `Status`, `BranchCode`, `CreatedAt`) must complete in $< 50$ms (p95) for datasets up to 500,000 records.
- **NFR-PERF-03**: Database indexes must be explicitly defined on:
  - `ApplicationNumber` (Unique Clustered/Non-Clustered Index)
  - `Status` (Non-Clustered Index for dashboard queries)
  - `BranchCode` (Non-Clustered Index for branch queues)
  - `Sla30DayDeadline`, `Sla90DayDeadline` (Non-Clustered Index for SLA background worker daemon queries)
  - `AgentCode`, `SourceCode` (Non-Clustered Index)

### 1.2 Concurrency & Data Integrity
- **NFR-CONC-01**: Optimistic Concurrency Control (OCC) must be enforced on `AgentApplication` and related entities using a `byte[] RowVersion` concurrency token.
- **NFR-CONC-02**: If a concurrent update collision occurs, EF Core must throw `DbUpdateConcurrencyException`, triggering a conflict notification to the user.

---

## 2. Security Baseline Requirements (SECURITY-BASE)

### 2.1 PII Protection & Data Encryption at Rest
- **NFR-SEC-01 (AES-256-GCM)**: Sensitive PII fields (`NationalIdOrTaxId`, `BankAccountNumber`, `Guarantor.NationalId`) must be encrypted at rest using AES-256-GCM via EF Core ValueConverters before persisting to MS SQL Server.
- **NFR-SEC-02 (SQL Injection Prevention)**: All database interactions must use parameterized SQL queries generated by EF Core LINQ expressions or parameterized stored procedures.
- **NFR-SEC-03 (ISO 27001 Audit Immutability)**: Every entity inherits `CreatedAt`, `CreatedBy`, `UpdatedAt`, `UpdatedBy`, `IsDeleted`, `DeletedAt`, `DeletedBy`. Deletions are strictly soft deletes managed via EF Core Global Query Filters (`e.IsDeleted == false`).

---

## 3. Resiliency Baseline Requirements (RESILIENCY-BASE)

### 3.1 Transient Fault Handling & Connection Recovery
- **NFR-RES-01 (Execution Strategy)**: EF Core must use SQL Server connection resiliency (`EnableRetryOnFailure(maxRetryCount: 5, maxRetryDelay: TimeSpan.FromSeconds(30), errorNumbersToAdd: null)`) to survive transient database network glitches and failovers.
- **NFR-RES-02 (Health Checks)**: Expose `/health/live` (Liveness) and `/health/ready` (Database ping check) endpoints.

---

## 4. Built-in Executive Approval & Notification Strategy
- **NFR-WF-01 (Internal E-Approval)**: Executive approval workflows (MD, Division Directors) are executed natively within this system (eliminating external EAS dependency).
- **NFR-NOTIF-01 (Email Notification Engine)**: High-priority email notifications with direct, secure review links are dispatched to approvers upon status transitions (`SUBMITTED_BRANCH` $\rightarrow$ `REVIEW_HEAD_OFFICE` $\rightarrow$ `PENDING_EXECUTIVE_APPROVAL` $\rightarrow$ `REVIEW_PREMIUM`).

---

## 5. Property-Based Testing (PBT) Invariants
- **PBT-01 (State Transition Invariants)**: Arbitrary sequences of state transitions must either transition according to the valid state machine progression or fail with `InvalidStateTransitionException` without corrupting entity state.
- **PBT-02 (Round-Trip PII Encryption)**: For any valid 13-digit Thai National ID or Bank Account Number, `Decrypt(Encrypt(plainText)) == plainText`.
